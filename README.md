# weekly-ai-tutor

Heavy AI users accumulate a quiet backlog of things they let the model handle without ever learning them. This tool looks at a week of real transcripts, finds the concepts that were outsourced rather than learned, and turns them into a short podcast lesson sized to whatever time you have.

**Status: early build, in progress.** This repo is being built incrementally, one real piece at a time — see `BUILD-SCHEDULE.md` for the day-by-day plan and `DESIGN.md` for the full architecture and gap-detection rubric. Nothing here is a stub described as finished work; each commit is what it says it is.

## What's implemented so far

- **Transcript schema and ingestion** (`weekly_ai_tutor/schema.py`, `weekly_ai_tutor/ingest.py`): a documented, tool-agnostic JSON transcript format, plus loaders that validate structure and report bad files without silently dropping them. See the docstring in `schema.py` for the exact expected shape.
- **Gap-detection gating** (`weekly_ai_tutor/gap_detection.py`): the 3 gating conditions from `DESIGN.md` (non-trivial delegation, no engagement signal, immediate accept), plus 5 additional signals (foundational, opted_out, boilerplate, already_understood, incident_context) needed for scoring — all evaluated via a single forced-tool-use Claude API call with a dependency-injected client. The 5 additional signals are optional in the response shape (default `False`), so this is a backward-compatible extension of day 2's contract. **Caveat:** no `ANTHROPIC_API_KEY` is available in the build sandbox, so `AnthropicGapDetectionClient`'s request/response plumbing is tested against a mocked SDK client, not a live call — see the module docstring.
- **Recurrence + foundational-weight scoring** (`weekly_ai_tutor/scoring.py`): takes a pool of `GapCandidate`s spanning one or more transcripts, filters to only those passing all 3 gates and not hard-excluded (opted_out/boilerplate/already_understood), groups by topic (exact-match — see below), and scores each group by `severity = recurrence_count x foundational_weight x incident_multiplier`. Incident-context candidates are down-weighted (0.5x when *every* occurrence was incident-driven), not excluded, per `DESIGN.md`'s "note it, don't rank it the same" language. Rework-cost weighting (`DESIGN.md` rubric item 6) is intentionally not implemented yet.
- **Topic clustering** (`weekly_ai_tutor/clustering.py`, DESIGN.md step 3 "dedup + cluster"): `scoring.py`'s exact-match topic grouping fragments the same underlying concept across different phrasings (e.g. "SQL joins" vs "joining tables in SQL" don't share a topic_key). `cluster_gap_candidates` filters a candidate pool to `should_flag` survivors, dedupes their topic_key values, sends them to Claude via a forced tool-use call to group by underlying concept, and validates the response structurally — every input topic must land in exactly one cluster, with no invented or dropped topics, or a `ClusteringResponseError` is raised. Regrouped candidates come back as `TopicCluster` objects (`canonical_topic`, `member_topic_keys`, `candidates`, `recurrence_count`). This module does not itself recompute `scoring.py`'s severity formula on top of clusters instead of exact-match groups — wiring the two together is left for the day the full pipeline gets assembled (day 8, CLI wiring). Same live-API caveat as `gap_detection.py`: `AnthropicClusteringClient` is tested against a mocked SDK client only, not a live call.
- **Curriculum fitting** (`weekly_ai_tutor/curriculum.py`, DESIGN.md's "prioritize + fit to time budget" step): `fit_curriculum(candidates, total_minutes)` is a pure deterministic greedy allocator — no Claude API call involved. It reserves 10% of the budget for intro/outro, sorts a small self-contained `CurriculumCandidate` (label + priority + recurrence_count) list by priority, selects topics at an 8-minute floor up to a 5-topic cap, then tops up selected topics with any leftover budget (up to a 12-minute ceiling each, derived from DESIGN.md's own script-template section lengths). Anything not selected is returned as `carried_over`, matching DESIGN.md's "carried to next week's backlog" language. `CurriculumPlan.__post_init__` includes a hard reconciliation check that intro/outro + topic minutes + unallocated minutes always sum to the total budget. Deliberately does not import `TopicCluster`/`ScoredGap` directly — that wiring is day 8's job.
- **Script generation** (`weekly_ai_tutor/script_generation.py`, DESIGN.md's 4-part script template): `generate_script(topic, minutes, source_descriptions, client)` produces a `TopicScript` (hook/concept/example/next_time + a `full_text` property) via a forced tool-use Claude API call. Privacy is enforced two ways: by API design, the function only ever accepts a topic string and a list of already-paraphrased source-description strings — never a raw `Transcript`/`Message` — so there's no code path for verbatim proprietary content to reach the prompt; and by output scan, `enforce_privacy` regex-checks every section (and the input source descriptions, before the API call even happens) for API-key/PEM-header/password-assignment-shaped patterns, raising `PrivacyViolationError` before a `TopicScript` is ever constructed. Same live-API caveat as `gap_detection.py`/`clustering.py`: `AnthropicScriptGenerationClient`'s request/response plumbing is tested against a fake SDK client, not a live call.
- **TTS rendering** (`weekly_ai_tutor/tts.py`, DESIGN.md's "render" step): `PiperSpeechSynthesisClient.synthesize(text)` turns script text into an `AudioSegment` (raw PCM + format metadata) using Piper — open-source, local, no API key. `synthesize_topic_script` re-runs `enforce_privacy` on a `TopicScript`'s `full_text` as a defense-in-depth check before handing it to a synthesis client, since audio is the last place a leak could surface before delivery. `concatenate_audio_segments` splices multiple segments together with a configurable silence gap (for joining topics into one episode later), and `write_wav_file`/`read_wav_file` handle plain WAV I/O — Piper's native output is 16-bit PCM, so this module works in WAV throughout; mp3 encoding is a later-day format-conversion step once ffmpeg/lame availability in the build sandbox has actually been checked. **Caveat:** this build sandbox can install `piper-tts` (verified against the actual installed 1.8.0 API via `inspect`, not assumed) but cannot download a voice model from Hugging Face (network policy blocks it), so `PiperSpeechSynthesisClient`'s file-existence check and chunk-to-`AudioSegment` conversion logic are real and tested, but synthesis has not been exercised against a real voice model — no one has heard real audio output from this yet. See `weekly_ai_tutor/tts.py`'s docstring for the one-time manual voice-model download step needed on a machine without that network restriction before live audio can be claimed as verified.

- **CLI wiring** (`weekly_ai_tutor/pipeline.py`, `weekly_ai_tutor/cli.py`, DESIGN.md pipeline steps 1-5): `pipeline.run_pipeline(transcripts_dir, total_minutes, gap_client, clustering_client, script_client)` ties every module above together end to end — ingest, gap-detect each transcript, pool and cluster the candidates, score each `TopicCluster` (`score_topic_cluster` is the missing piece `clustering.py` deferred: `scoring.py`'s severity formula applied over a cluster's pooled candidates instead of an exact-match `topic_key` group), fit the scored clusters to the time budget via `curriculum.fit_curriculum`, and generate a script per selected topic — never passing raw transcript content into `generate_script`, only the cluster's already-paraphrased candidate descriptions. Returns an `EpisodePlan` (selected `scripts`, `carried_over_topics`, and diagnostic `transcripts_loaded`/`gap_candidates_found` counts, so "found 0 gaps" and "found 12, all filtered out" are reported as distinct honest outcomes rather than collapsed). `cli.py` exposes this as `python3 -m weekly_ai_tutor run --transcripts-dir DIR --minutes N` (optionally `--output-dir DIR` to write one `.txt` script per topic, `--model` to override the Claude model) — argument parsing and I/O only, with all pipeline logic living in `pipeline.py` so it's fully unit-testable without a CLI invocation. There is no `setup.py`/`pyproject.toml` yet, so this isn't an installed `weekly-ai-tutor` console script — invoke via `python3 -m weekly_ai_tutor` or `python3 -m weekly_ai_tutor.cli`. **Caveat:** same live-API caveat as the modules above — `run_command` constructs the real `Anthropic*Client` instances, so this command has not been run end-to-end against real transcripts in this sandbox; what's tested is argument parsing, output rendering, and file-writing with the three clients replaced by fakes.

Everything else in the pipeline (audio rendering/episode assembly on top of `EpisodePlan.scripts`, delivery) is not built yet — see `BUILD-SCHEDULE.md`.

## Setup

```bash
pip install -r requirements.txt
python3 -m pytest tests/
```

## Why Piper for text-to-speech

Piper is open-source and runs locally — no API key, no per-episode cost, no sending transcript-derived content to a third-party TTS service. The trade-off: voice models are downloaded from Hugging Face on first use, so a one-time internet-connected setup step is required before audio rendering works. See `weekly_ai_tutor/tts.py`'s module docstring for exactly what has and hasn't been verified in this build sandbox.
